# The asset universe, one file per chain

`pnpm risk:assets <chain>` (`docs/risk/PLAN-ASSETS.md` AS.2 and AS.3, gate `ASSET-UNIVERSE`, decision DA2) writes `solana.json` and `robinhood.json` in this folder: every token of the classes the product knows on that chain, whether or not a plan may hold it, each with a status and its reason. They are generated and committed, as the stock lists in `scripts/risk/universe/` are, and those stock lists are not changed: a tracked stock's row here names its row there (`tracked`) and copies neither its pools nor its oracle.

```sh
pnpm risk:assets solana      # the Solana builder, scripts/risk/assets/solana.ts
pnpm risk:assets robinhood   # the Robinhood Chain builder, scripts/risk-evm/assets.ts
```

## How a list is made

- **`build.ts`** loads the chain's builder (each exports `buildList(args: string[]): Promise<{ list, lines? }>`), validates what it returns with `UniverseList` (`packages/schemas/src/asset-universe.ts`), checks that every verdict of `<chain>.verdicts.json` names a row of the list, writes `<chain>.json`, formats it, and prints the counts per category, status, class, deciding layer and null reason and each read's calls and seconds. A list that does not validate, or a verdict for an address that is not a row, writes nothing.
- **The builder** reads the chain and its listings and decides which verdict rules each token matches. It never types a verdict.
- **The verdicts** are `<chain>.verdicts.json` (schema `UniverseVerdicts`), reviewed by hand: `rules` for every token a listing names in one way, each with its sources, and `verdicts` for one address each. The builder refuses a verdict for an address it did not read (`unreadVerdicts`), and the command checks it again on the list.
- **A row** is joined by `universeRow` in `packages/risk/src/assets/universe.ts`: the identity read on chain, the context from the chain's own files (pools, oracle, shelf, tracked row), and the verdict fields, taken in this order with the later winning: what the builder derived by a method it states, each matching rule in the table's order (each once), the token's own verdict; the row's `decidedBy` names the layers. The class is always the category's (`CATEGORY_CLASS`). A field no layer sets stops the run, naming the token and the field.
- **What the schema refuses besides missing reasons:** a status that offers what the plan holds out (a permissioned token, a token with a maturity or in another currency, a token with no class, a dollar-yield token with no leg type: these are `held_out` or `excluded`); a tracked stock without its tracked row, or any other row pointing at one; a standard, a symbol source, an authority or the issuer registry of the other chain; an EVM implementation without a proxy.

Nothing in a row is a price, a TVL, a supply or a yield: those are observations with their own time (AS.4 and AS.5).

## Robinhood Chain

`pnpm risk:assets robinhood` (AS.3). The reads and how often each endpoint is asked are in `scripts/risk-evm/README.md` ("The asset universe"); the builder is `scripts/risk-evm/assets.ts`, the list from the reads `scripts/risk-evm/assets-list.ts` (no I/O), the decoders `packages/risk/src/assets/evm.ts`.

**Inputs.** Read: the issuer's registry (`https://api.robinhood.com/rhj/assets`, every row), Chainlink's directory (`feeds-robinhood-mainnet.json`), DexScreener's search and token pairs on the chain, and the chain at one block. Files: the tracked list (`scripts/risk/universe/robinhood.json`), the shelf fixture (`packages/engine/src/personal/fixtures/shelves/robinhood-yield.json`), the deploy record (`deployments/robinhood-testnet.json`), `content/stocks/robinhood.json`, `packages/engine/src/personal/leg-types.ts`, the screening note and its input list (`docs/vault/research/yield-shelf/robinhood.md`, `inputs/robinhood_chain_yield_assets.csv`: every full address written in them is a name to read), the discovery file of RU.2 (`RISK_EVM_DIR`, read only) and the market calendar.

**Which tokens are rows.** Every token of the registry; the gas coin (`0xeeee…eeee`, standard `native`); and each token another listing named that a verdict or a rule decides. DexScreener's names are read on chain when the symbol names a class (it holds USD or EUR, or is one of the prompt's names, a base asset of the directory or a symbol of the registry) or when the verdict table names the address; every such token, and every token the note names, must be decided or the build stops, naming it. Other names (memecoins, launch tokens) are not read and not enumerated (DA6). An address that does not answer `decimals()` and `symbol()` is not a token and never a row (the note's pools, factory, quoter and the rUSDG vault).

**One rule for memecoins and protocols, both chains** (ASSET-1 review, 2026-10-12). What CoinGecko files a token under decides it, by one list for both chains: Robinhood Chain reads the categories' names, matched whole; the Solana list reads the same categories by their CoinGecko ids (its builder is on the branch `universe/assets-solana`, 5e9ca713, which this branch does not change):

- A token in any memecoin category is **not a row**. A memecoin category is one whose name holds "Meme" and not "Ecosystem", or holds "Themed": "Meme", "Robinhood Chain Meme", "Dog-Themed", "Wall Street Bets Themed".
- A token is **`governance`** only when CoinGecko files it under one of exactly these nine categories: Decentralized Exchange (DEX), Lending/Borrowing Protocols, Perpetuals, Derivatives, Oracle, Bridge Governance Tokens, Infrastructure, Liquid Staking Governance Tokens, Yield Aggregator; or under Launchpad when it is the launch pad's own token (CoinGecko keeps a category named "<the pad> Launchpad" of the tokens launched on it: "Pons Launchpad" for Pons); or when its own verdict cites its project's own page naming the protocol it governs. An own page is what `isOwnPage` (`scripts/risk-evm/assets-list.ts`) accepts: an `https://` URL whose host is not a listing, an aggregator, a directory or an explorer (CoinGecko, GeckoTerminal, CoinMarketCap, Jupiter, DexScreener, DEXTools, Birdeye, DefiLlama and llama.fi, Chainlink's sites and its feed directory, the issuer's registry, any `*scan` or `explorer` host, Blockscout); a repository path or any text that is not such a URL never is. The builder stops on a `governance` row that stands on neither, naming it. Nothing else admits a token: not a tag such as DeFi or AI, not a chain (layer 1 or 2), not "Governance" alone, not cross-chain communication, prediction markets, gaming, AI frameworks or DePIN, not what it was launched on or carried by.
- A liquid staking token itself (Liquid Staking Tokens, Liquid Staked ETH, Liquid Restaking Tokens) is `liquid_staking`, not `governance`.
- A token's own verdict wins over every rule, but never makes a memecoin a row: the builder stops on a verdict for a token CoinGecko files as a memecoin, as the Solana builder refuses a row CoinGecko files as one.

**Crypto beyond the listings** (Rodrigo, 2026-10-11). Two more lists name tokens with their address on the chain: CoinGecko's token list for Robinhood Chain (`tokens.coingecko.com/robinhood/all.json`) and Chainlink CCIP's token directory (`docs.chain.link/api/ccip/v1/tokens`, the tokens CCIP moves, with their address on each chain). A token of either, outside the registry, is **selected** when its DexScreener pairs (`tokens/v1/robinhood/<30 addresses>`, read the same day) traded $10,000 or more over 24 hours together, or when its symbol, in upper case, is the base asset of a Chainlink feed of the directory. The volume selects only: it is kept in the frozen reads and never in a row. Each selected token, each verdict's token and each row of a committed list is looked up on CoinGecko (the chain's memecoin category `robinhood-chain-meme`, the list of every coin with its addresses, every category's name, and the coin's page) and decided by the rule above: a protocol's token is a row by `crypto-protocol` (category `governance`, its project as issuer, its CoinGecko page as source; `candidate`, DA6), a liquid staking token by `crypto-liquid-staking`; a memecoin (`meme`), a token with no protocol category (`no_protocol_category`) and one CoinGecko has no page for (`not_on_coingecko`) are not rows. A wrapped coin of another chain or a staking token may be a row by its own verdict, with its source (TAO, wstETH, cbBTC, LINK by CCIP's directory; LINK is `governance` by its Oracle category, not by those sources). `stated.cryptoLeftOut` counts what the selection left out, by reason. CoinGecko is read keyless, one call every six seconds, a minute's wait on a refusal for rate.

**No row leaves unsaid, and an id stays with its address.** Every address of every committed version of `robinhood.json` (its git history) and every verdict's address is read on chain on every run, whatever that day's search returned. Such a row stays a row unless it no longer answers as a token or the rules above now say it is not one (a memecoin by CoinGecko, or a `governance` row with no protocol category and no own page); each row that leaves is named in `stated.leftTheList` with why. A row keeps the id its address had in the newest committed list that held it; the exceptions are an id over the schema's 96 characters and an id the product's deploy records use (`packages/sdk/deployments/*.json`, for example `robinhood:usdc`, the cash id of the mock and local records) on a row that is not listed. A bare id goes only to a listed row or to the one row whose symbol gives it; any other takes a dash and six hex digits of its address. The committed lists the run started from are frozen with its reads, so the test rebuilds the ids.

**How a rule's `match` is read.** Each key must hold for the token: `listing` is a listing that named it (`issuer_registry`, `screening_note`, `position_manager_weth9`, `dexscreener`, `coingecko`, `chainlink_ccip`, `previous_list`, `verdict_table`); `coingecko` is what CoinGecko says of a token outside the registry (`protocol`, `liquid_staking`, `stablecoin`, `meme`, `no_protocol_category`, `not_on_coingecko`); `protocol` is `yes` where that is `protocol` or `liquid_staking`, else `no`; `inUniverse` is `yes` for a token the selection kept or a row of a committed list; `classTable` is `CLASS_BY_UNDERLYING` of `scripts/risk/universe/list.ts` at the registry's symbol (SPY and QQQ `etf`, GLD `gold`, SLV and USO `commodity`, SGOV `dollar_yield`), `stock` for every other registry symbol; `symbolOf` is `issuer_registry` for a token outside the registry whose symbol is a registry token's; `claims` is, for such a token, `issuer_product` where its name names the issuer or that stock (it holds "Robinhood", is the symbol, or begins with the first word of the stock's name in the registry: "GameStop", "Palantir", "SpaceX"), else `none` ("Pawlantir", "A Meme Dog", "NetNet"). A key the builder does not know stops the build.

**The rule over the registry.** `issuer-registry` (issuer Robinhood, a tokenization issuer; access, how dividends reach a holder and how a token is minted and redeemed `not_read_on_an_issuer_source`, each said in `unverified`) and one class rule per `classTable` value: `tokenized_stock`, `tokenized_etf`, `tokenized_gold`, `tokenized_commodity`, `treasury_fund_open`. The builder derives the underlying (the registry's symbol), the leg types (leg-types.ts at the symbol, for SGOV `rate`; none for the others) and the status.

**Status.** `listed`: a tracked stock (`tracked_stock`; its oracle and pools are read in its tracked row, `in_tracked_row`), or a token a deploy record names (`deploy_record`: the model of an asset of `deployments/robinhood-testnet.json` by its `modelOf`, matched to the registry token of that symbol, or the cash token `contracts/script/config/4663.json` names by address, `cashToken`). A registry token that is neither: `candidate`, "outside the cut that names the tracked stocks (gate UNIVERSE)" (DA16). The dollar and yield tokens of the note: its verdict (add with caution `candidate`; hold `held_out`; out `held_out`, or `excluded` where the reason is filter 4, not live; the PT `fixed_maturity`, `held_out`), with `verdictSource` naming the note and section. Crypto: `candidate` (DA6) where a listing gave the address with a source (WETH9() of the position manager, the note's input list), `held_out` where only DexScreener names it. Pool shares and yield claims: `held_out` (no class). A dollar not screened: `held_out`. A token not shown to be the asset it names (the note's "USDT", two "GOLD"): `held_out`, with what was read in `unverified`. Not the asset it claims: `excluded`, by the rule `not-the-issuers-stock-token` for a token with a registry stock's symbol whose name claims that stock and that the registry does not hold, by `registry-symbol-not-a-protocol` for one with such a symbol that does not claim the stock and that no protocol category names (a symbol alone never excludes a protocol's token: NET, a lending protocol's by CoinGecko, is decided by its categories), by its own verdict where its own name says so (two "USDC" that call themselves dog and cat coins, a WBTC that calls itself We Buy The Cat).

**What a verdict writes.** A decision with its source, never a figure: no price, rate, yield, TVL, discount or cost sits in a verdict's text; it points at the note's section instead. `access` is written only as a source states it (the note's reading of a token's transfer gates, an issuer's eligibility terms), else `null` with `not_read`.

**What the code says.** `proxy` from the EIP-1967 slots (implementation, admin, beacon; a beacon's `implementation()`): `false` where they are zero and the code has no DELEGATECALL, or the code is an EIP-1167 clone whose target has none; `null` where the code delegates without a slot or a clone's target delegates (the target's own slots are read and named in `read`). `pausable` and `blacklist` are `true` where the code that runs (a proxy and its implementation, or a clone's target) pushes a selector below, or where that code is a facet router (it pushes `getFacet(bytes4)` 112b6a67) and `getFacet(<selector>)` asked of the token names a facet whose own code pushes it; `null` (`code_may_run_elsewhere`) where none is found and the code that runs has a DELEGATECALL; `false` only where none is found in code that does not delegate.

`false` says only that none of these names is in code that runs nothing else. `owner` is `owner()`. `admin`: behind a beacon, `owner()` of the beacon; else the EIP-1967 admin slot. An empty admin slot is `none` only on a token that is not a proxy; on a proxy whose implementation pushes an upgrade selector it is `uups_upgrade_in_implementation` (the implementation upgrades itself), on another proxy `admin_slot_empty_on_proxy`, on code that delegates without a slot `admin_slot_empty_code_delegates`, each naming what `owner()` and `defaultAdmin()` of the token answer. Who an AccessControl contract lets act is not read.

**What is stated in the file** (`stated`): the rows, the enumeration, the class names, the rules, what is derived, `listed`, the ids, the identity, the standard, the extensions, the authorities, the oracle (the oracle map's rule, letters as written; no feed for a token whose issuer no verdict names, `issuer_not_confirmed`; `feed_named_in_other_case_not_tied` where the directory names the symbol only in another case; no answer stored), the pools (a pool with a registry stock token counted from the discovery file of Oct 5, confirmed when a chain source names it; any other from this run's DexScreener answers, unconfirmed; the venues that are not Uniswap v3 or v4 are not read, D4, `BYREAL-D4`), and that nothing is a figure.
