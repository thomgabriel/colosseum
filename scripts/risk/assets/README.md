# The asset universe, one file per chain

`pnpm risk:assets <chain>` (`docs/risk/PLAN-ASSETS.md` AS.2 and AS.3, gate `ASSET-UNIVERSE`, decision DA2) writes `solana.json` and `robinhood.json` in this folder: every token of the classes the product knows on that chain, whether or not a plan may hold it, each with a status and its reason. They are generated and committed, as the stock lists in `scripts/risk/universe/` are, and those stock lists are not changed: a tracked stock's row here names its row there (`tracked`) and copies neither its pools nor its oracle.

```sh
pnpm risk:assets solana      # the Solana builder, scripts/risk/assets/solana.ts
pnpm risk:assets robinhood   # the Robinhood Chain builder, scripts/risk-evm/assets.ts
```

## How a list is made

- **`build.ts`** loads the chain's builder (each exports `buildList(args: string[]): Promise<{ list, lines? }>`), validates what it returns with `UniverseList` (`packages/schemas/src/asset-universe.ts`), checks that every verdict of `<chain>.verdicts.json` names a row of the list, writes `<chain>.json`, formats it, and prints the counts per category, status, class, deciding layer and null reason and each read's calls and seconds. A list that does not validate, or a verdict for an address that is not a row, writes nothing.
- **The builder** reads the chain and its listings and decides which verdict rules each token matches. It never types a verdict.
- **The verdicts** are `<chain>.verdicts.json` (schema `UniverseVerdicts`), reviewed by hand: `rules` for every token a listing names in one way, each with its sources, and `verdicts` for one address each. The builder refuses a verdict for an address it did not read (`unreadVerdicts`), and the command checks it again on the list.
- **A row** is joined by `universeRow` in `packages/risk/src/assets/universe.ts`: the identity read on chain, the context from the chain's own files (pools, oracle, shelf, tracked row), and the verdict fields, taken in this order with the later winning: what the builder derived by a method it states, each matching rule in the table's order (each once), the token's own verdict; the row's `decidedBy` names the layers. The class is always the category's (`CATEGORY_CLASS`). A field no layer sets stops the run, naming the token and the field.
- **What the schema refuses besides missing reasons:** a status that offers what the plan holds out (a permissioned token, a token with a maturity or in another currency, a token with no class, a dollar-yield token with no leg type: these are `held_out` or `excluded`); a tracked stock without its tracked row, or any other row pointing at one; a standard, a symbol source, an authority or the issuer registry of the other chain; an EVM implementation without a proxy.

Nothing in a row is a price, a TVL, a supply or a yield: those are observations with their own time (AS.4 and AS.5).

## Robinhood Chain

`pnpm risk:assets robinhood` (AS.3). The reads and how often each endpoint is asked are in `scripts/risk-evm/README.md` ("The asset universe"); the builder is `scripts/risk-evm/assets.ts`, the list from the reads `scripts/risk-evm/assets-list.ts` (no I/O), the decoders `packages/risk/src/assets/evm.ts`.

**Inputs.** Read: the issuer's registry (`https://api.robinhood.com/rhj/assets`, every row), Chainlink's directory (`feeds-robinhood-mainnet.json`), DexScreener's search and token pairs on the chain, and the chain at one block. Files: the tracked list (`scripts/risk/universe/robinhood.json`), the shelf fixture (`packages/engine/src/personal/fixtures/shelves/robinhood-yield.json`), the deploy record (`deployments/robinhood-testnet.json`), `content/stocks/robinhood.json`, `packages/engine/src/personal/leg-types.ts`, the screening note and its input list (`docs/vault/research/yield-shelf/robinhood.md`, `inputs/robinhood_chain_yield_assets.csv`: every full address written in them is a name to read), the discovery file of RU.2 (`RISK_EVM_DIR`, read only) and the market calendar.

**Which tokens are rows.** Every token of the registry; the gas coin (`0xeeee…eeee`, standard `native`); and each token another listing named that a verdict or a rule decides. DexScreener's names are read on chain when the symbol names a class (it holds USD or EUR, or is one of the prompt's names, a base asset of the directory or a symbol of the registry) or when the verdict table names the address; every such token, and every token the note names, must be decided or the build stops, naming it. Other names (memecoins, launch tokens) are not read and not enumerated (DA6). An address that does not answer `decimals()` and `symbol()` is not a token and never a row (the note's pools, factory, quoter and the rUSDG vault).

**One rule for memecoins and protocols, both chains** (ASSET-1 review, 2026-10-12). What CoinGecko files a token under decides it, by one list for both chains: Robinhood Chain reads the categories' names, matched whole; the Solana list reads the same categories by their CoinGecko ids (its builder is on the branch `universe/assets-solana`, 5e9ca713, which this branch does not change):

- A token in any memecoin category is **not a row**. A memecoin category is one whose name holds "Meme" and not "Ecosystem", or holds "Themed": "Meme", "Robinhood Chain Meme", "Dog-Themed", "Wall Street Bets Themed".
- A token is **`governance`** only when CoinGecko files it under one of exactly these nine categories: Decentralized Exchange (DEX), Lending/Borrowing Protocols, Perpetuals, Derivatives, Oracle, Bridge Governance Tokens, Infrastructure, Liquid Staking Governance Tokens, Yield Aggregator; or under Launchpad when it is the launch pad's own token (CoinGecko keeps a category named "<the pad> Launchpad" of the tokens launched on it: "Pons Launchpad" for Pons); or when its own verdict cites its project's own page naming the protocol it governs. Nothing else admits a token: not a tag such as DeFi or AI, not a chain (layer 1 or 2), not "Governance" alone, not cross-chain communication, prediction markets, gaming, AI frameworks or DePIN, not what it was launched on or carried by.
- A liquid staking token itself (Liquid Staking Tokens, Liquid Staked ETH, Liquid Restaking Tokens) is `liquid_staking`, not `governance`.
- A token's own verdict wins over every rule; a memecoin is a row only by one.

**Crypto beyond the listings** (Rodrigo, 2026-10-11). Two more lists name tokens with their address on the chain: CoinGecko's token list for Robinhood Chain (`tokens.coingecko.com/robinhood/all.json`) and Chainlink CCIP's token directory (`docs.chain.link/api/ccip/v1/tokens`, the tokens CCIP moves, with their address on each chain). A token of either, outside the registry, is **selected** when its DexScreener pairs (`tokens/v1/robinhood/<30 addresses>`, read the same day) traded $10,000 or more over 24 hours together, or when its symbol, in upper case, is the base asset of a Chainlink feed of the directory. The volume selects only: it is kept in the frozen reads and never in a row. Each selected token, each verdict's token and each row of a committed list is looked up on CoinGecko (the chain's memecoin category `robinhood-chain-meme`, the list of every coin with its addresses, every category's name, and the coin's page) and decided by the rule above: a protocol's token is a row by `crypto-protocol` (category `governance`, its project as issuer, its CoinGecko page as source; `candidate`, DA6), a liquid staking token by `crypto-liquid-staking`; a memecoin (`meme`), a token with no protocol category (`no_protocol_category`) and one CoinGecko has no page for (`not_on_coingecko`) are not rows. A wrapped coin of another chain or a staking token may be a row by its own verdict, with its source (TAO, wstETH, cbBTC, LINK by CCIP's directory). `stated.cryptoLeftOut` counts what the selection left out, by reason. CoinGecko is read keyless, one call every six seconds, a minute's wait on a refusal for rate.

**No row leaves unsaid, and an id stays with its address.** Every address of every committed version of `robinhood.json` (its git history) and every verdict's address is read on chain on every run, whatever that day's search returned. Such a row stays a row unless it no longer answers as a token or the rules above now say it is not one (a memecoin by CoinGecko); each row that leaves is named in `stated.leftTheList` with why. A row keeps the id its address had in the newest committed list that held it; the exceptions are an id over the schema's 96 characters and an id the product's deploy records use (`packages/sdk/deployments/*.json`, for example `robinhood:usdc`, the cash id of the mock and local records) on a row that is not listed. A bare id goes only to a listed row or to the one row whose symbol gives it; any other takes a dash and six hex digits of its address. The committed lists the run started from are frozen with its reads, so the test rebuilds the ids.

**How a rule's `match` is read.** Each key must hold for the token: `listing` is a listing that named it (`issuer_registry`, `screening_note`, `position_manager_weth9`, `dexscreener`, `coingecko`, `chainlink_ccip`, `previous_list`, `verdict_table`); `coingecko` is what CoinGecko says of a token outside the registry (`protocol`, `liquid_staking`, `stablecoin`, `meme`, `no_protocol_category`, `not_on_coingecko`); `protocol` is `yes` where that is `protocol` or `liquid_staking`, else `no`; `inUniverse` is `yes` for a token the selection kept or a row of a committed list; `classTable` is `CLASS_BY_UNDERLYING` of `scripts/risk/universe/list.ts` at the registry's symbol (SPY and QQQ `etf`, GLD `gold`, SLV and USO `commodity`, SGOV `dollar_yield`), `stock` for every other registry symbol; `symbolOf` is `issuer_registry` for a token outside the registry whose symbol is a registry token's; `claims` is, for such a token, `issuer_product` where its name names the issuer or that stock (it holds "Robinhood", is the symbol, or begins with the first word of the stock's name in the registry: "GameStop", "Palantir", "SpaceX"), else `none` ("Pawlantir", "A Meme Dog", "NetNet"). A key the builder does not know stops the build.

**The rule over the registry.** `issuer-registry` (issuer Robinhood, a tokenization issuer; access, how dividends reach a holder and how a token is minted and redeemed `not_read_on_an_issuer_source`, each said in `unverified`) and one class rule per `classTable` value: `tokenized_stock`, `tokenized_etf`, `tokenized_gold`, `tokenized_commodity`, `treasury_fund_open`. The builder derives the underlying (the registry's symbol), the leg types (leg-types.ts at the symbol, for SGOV `rate`; none for the others) and the status.

**Status.** `listed`: a tracked stock (`tracked_stock`; its oracle and pools are read in its tracked row, `in_tracked_row`), or a token a deploy record names (`deploy_record`: the model of an asset of `deployments/robinhood-testnet.json` by its `modelOf`, matched to the registry token of that symbol, or the cash token `contracts/script/config/4663.json` names by address, `cashToken`). A registry token that is neither: `candidate`, "outside the cut that names the tracked stocks (gate UNIVERSE)" (DA16). The dollar and yield tokens of the note: its verdict (add with caution `candidate`; hold `held_out`; out `held_out`, or `excluded` where the reason is filter 4, not live; the PT `fixed_maturity`, `held_out`), with `verdictSource` naming the note and section. Crypto: `candidate` (DA6) where a listing gave the address with a source (WETH9() of the position manager, the note's input list), `held_out` where only DexScreener names it. Pool shares and yield claims: `held_out` (no class). A dollar not screened: `held_out`. A token not shown to be the asset it names (the note's "USDT", two "GOLD"): `held_out`, with what was read in `unverified`. Not the asset it claims: `excluded`, by the rule `not-the-issuers-stock-token` for a token with a registry stock's symbol whose name claims that stock and that the registry does not hold, by `registry-symbol-not-a-protocol` for one with such a symbol that does not claim the stock and that no protocol category names (a symbol alone never excludes a protocol's token: NET, a lending protocol's by CoinGecko, is decided by its categories), by its own verdict where its own name says so (two "USDC" that call themselves dog and cat coins, a WBTC that calls itself We Buy The Cat).

**What a verdict writes.** A decision with its source, never a figure: no price, rate, yield, TVL, discount or cost sits in a verdict's text; it points at the note's section instead. `access` is written only as a source states it (the note's reading of a token's transfer gates, an issuer's eligibility terms), else `null` with `not_read`.

**What the code says.** `proxy` from the EIP-1967 slots (implementation, admin, beacon; a beacon's `implementation()`): `false` where they are zero and the code has no DELEGATECALL, or the code is an EIP-1167 clone whose target has none; `null` where the code delegates without a slot or a clone's target delegates (the target's own slots are read and named in `read`). `pausable` and `blacklist` are `true` where the code that runs (a proxy and its implementation, or a clone's target) pushes a selector below, or where that code is a facet router (it pushes `getFacet(bytes4)` 112b6a67) and `getFacet(<selector>)` asked of the token names a facet whose own code pushes it; `null` (`code_may_run_elsewhere`) where none is found and the code that runs has a DELEGATECALL; `false` only where none is found in code that does not delegate.

An empty admin slot is `none` only on a token that is not a proxy; on a proxy whose implementation pushes an upgrade selector it is `uups_upgrade_in_implementation` (the implementation upgrades itself), on another proxy `admin_slot_empty_on_proxy`, on code that delegates without a slot `admin_slot_empty_code_delegates`, each naming what `owner()` and `defaultAdmin()` of the token answer. Who an AccessControl contract lets act is not read.

**What is stated in the file** (`stated`): the rows, the enumeration, the class names, the rules, what is derived, `listed`, the ids, the identity, the standard, the extensions, the authorities, the oracle (the oracle map's rule, letters as written; no feed for a token whose issuer no verdict names, `issuer_not_confirmed`; `feed_named_in_other_case_not_tied` where the directory names the symbol only in another case; no answer stored), the pools (a pool with a registry stock token counted from the discovery file of Oct 5, confirmed when a chain source names it; any other from this run's DexScreener answers, unconfirmed; the venues that are not Uniswap v3 or v4 are not read, D4, `BYREAL-D4`), and that nothing is a figure.

## Solana

```sh
DOTENV_CONFIG_PATH=<main checkout>/.env pnpm risk:assets solana \
  --registry <main checkout>/data/risk/registry-20261001T0139.json \
  --reads-dir <main checkout>/data/assets/solana     # live: reads, saves them, writes solana.json
pnpm risk:assets solana --from <solana-reads-<stamp>.json[.gz]>   # rebuild from saved reads, no network
```

The builder is `solana.ts` (all I/O) and `solana-list.ts` (the list from the reads; no I/O, no clock). The byte decoders are `packages/risk/src/assets/spl-mint.ts` (`decodeMint`, `decodeMetaplexMetadata`, `solanaIdentity`), tested on frozen mainnet accounts. `SOLANA_RPC_URL` loads through dotenv; without it the scripts fall back to the public RPC.

A Jupiter token is a candidate when it carries a tag a rule asks for or has a verdict; every address another source names is a candidate.

| Key | Holds when |
|---|---|
| `jupiterTag` | Jupiter's verified list carries the tag for the token |
| `minter` | the mint authority read on chain is this address |
| `freezeAuthority`, `permanentDelegate` | that authority, read on chain, is this address |
| `program` | the token program read on chain is `spl` or `token2022` |
| `nameEndsWith` | the name the chain answers ends with this text |
| `nameKind` | what the name method (`kindOfName`) reads in a stock issuer's token's name: `stock`, `equity_etf`, `gold_fund`, `commodity_fund`, `treasury_fund`, `bond_fund`, `crypto_fund`, `leveraged_etf` |
| `listedIn` | the token is on today's shelf that way (`structurer_registry`, `deploy_record`, `tracked_stock`), or `any`, or `none` |

The stock issuers' rules rest on keys read on chain: one mint authority for xStocks and for Ondo, one freeze authority and permanent delegate for Backpack's tokens. The `lst` rule rests on Jupiter's tag alone, as no key read on chain is shared by the stake pools. A stock issuer's rule is matched first, so the name method can read the ticker; then every rule is matched. A token Jupiter tags `deprecated` is not a row, nor one whose rules leave a verdict field unset; both are named in `stated.rules`.

**What the builder derives**, the lowest layer of `decidedBy`, only for a token of a stock issuer's rule (`xstocks`, `ondo-global-markets`, `backpack-securities`): `underlying`, the chain's symbol less the issuer's suffix (`x`, `on`; Backpack's symbol is the ticker); `category`, from what the name the chain answers says the token is (`kindOfName` in `solana-list.ts`, tested on real names). The tracked list's class table (`CLASS_BY_UNDERLYING`: SPY and QQQ funds of shares, GLD gold, SLV and USO commodities, SGOV Treasuries) wins where it names the ticker. Otherwise a name with no fund word (ETF, ETN, Fund, Index, a fund-only sponsor such as iShares, SPDR or Vanguard, an index such as S&P 500 or Russell 2000) is a stock; a fund is, in this order, leveraged or inverse (2x, 3x, Bull, Bear, UltraPro, ProShares Ultra or Short), of crypto assets, of gold, of another commodity (miners, services and producers are shares, not the metal), of Treasuries or government bonds, of other bonds or income, else of shares. Categories: a stock `tokenized_stock`, a fund of shares `tokenized_etf`, gold `tokenized_gold`, a commodity `tokenized_commodity`, Treasuries `treasury_fund_open` with no leg type (`not_screened_on_solana`), a leveraged, crypto or bond fund `tokenized_etf`. The rules `stock-issuer-*` hold out every fund that is not screened. A name without a fund word is a stock whatever the token is (JPSTx, a short-bond fund, is one).

**Context.** `id`: the tracked list's, else the shelf fixture's, else `solana:<slug of the chain's symbol>` (`+` as plus, `*` as star); two rows on one slug each take the first six characters of their address. `listedIn`: by mint in the structurer's registry; as the model of a test-network token (`modelOf`, matched to the one named mint that answers that symbol); a tracked stock. A tracked stock's row names its tracked row and reads its pools and oracle there (`in_tracked_row`). `oracle`: a Scope entry of the Scope table, else a one-entry Scope chain of a Kamino reserve of the lending import; `no_scope_entry` where a reserve of the import holds the token and names no chain, `scope_not_read` where none does (the import holds only the xStocks markets). **Status rules**, which the verdicts follow: `listed` where `listedIn` is not empty; a stock token outside the cut that names the tracked stocks `candidate` (DA16); a fund among them that is not screened (Treasuries, bonds, crypto, leveraged or inverse) `held_out`; dollar yield by the research note's verdict (add, add with caution: `candidate`; hold: `held_out`; out: `held_out` or `excluded` by its reason), `verdictSource` naming the note and section; a dollar-yield token the research has not screened `held_out`; permissioned funds `held_out` (DA4); another currency `held_out` (USD-ONLY, DA7); crypto `candidate` (DA6); a maturity or no class `held_out`; defunct, exploit-linked or not the asset it claims `excluded`. Leg types come from the note and are held to `packages/engine/src/personal/leg-types.ts` by the shelf fixture's symbol: a difference stops the run.

**`access`** is set only where a source says it: `permissioned` (an allowlist or terms that bar the holder: the permissioned funds, eUSX), `front_end_geo_blocked` (the issuer bars countries from minting or buying: USDY, the Etherfuse tokens, ONyc), else `null`, `not_read`.

**What the list states** (`stated`): the scope and enumeration with their counts; how identity, ids, rules, derived fields, status, leg types, oracle and pools are read; what the xStocks and Ondo tokens are on chain (their programs, authorities, metadata hosts and extension sets, counted); the verified tokens that are not rows, by reason, with the ones carrying a class tag listed for review; the mints other sources name that are not rows; DefiLlama's stablecoins with no row; the issuer pages' answers; what is not enumerated (BRS, memecoins, Base, the Kamino deposit tokens no listing names, PUMP and MET).

### The crypto selection (Rodrigo, 2026-10-11)

Beyond SOL, the LSTs and the named wrapped and governance tokens, the list takes every token of Jupiter's verified list that is **tagged `major` or `strict`, or traded at least $50,000 on Jupiter in the 24 hours before the read** (`SELECTION_FLOOR_USD`; its `stats24h` buy and sell volume is kept in the saved reads, frozen with them so the test re-derives the pick, and is on no row). Each picked token is a row with a verdict of its own, or is listed in `solana.left-out.json` with its reason and where it was read; a token CoinGecko files as a meme is counted by the builder.

**The meme and protocol calls (Rodrigo, 2026-10-11, the same rule on both chains)** come from CoinGecko's categories, whose members `coingecko-categories.ts` reads beforehand (keyless, about a call every eight seconds, resumable) and the build takes with `--categories <file>`, freezing them with the reads. A token in any of CoinGecko's meme categories is not a row: every category whose name says Meme (an ecosystem's category aside) or Themed, 37 on 2026-10-11 (`MEME_CATEGORIES`). `pnpm risk:assets-import <solana|robinhood|all>` reads every metric of every row of a list from free sources (DA8) and writes `asset_observations` (one row per chain, token, metric, source and time; migration `0021`); the aggregators' prices go to `risk_price_observations` under their own source. Gate `ASSET-METRICS`.

Options: `--dry-run` (no row, no answers file, no run-log line), `--metrics` (any of the nine below and `price_usd`), `--from` (one chain, no network), `--data-dir`, `--solana-prices none|unresolved|all` (below), `--answers-out <file>` (the answers to a file of your choice, a dry run included), `--only` and `--show` (some tokens: a try, a fixture's run; never a job's run). **Where the code is.** Pure, in `packages/risk/src/assets/` (no I/O, no clock, no `process.env`, never `engine`): `metrics.ts` (one builder per metric, its method in `method`, `method_version` `asset-metrics-0.1`, its parts in `detail`; `metricPlan`, which read answers a metric of a row or why none does), `metric-rows.ts` (a run's answers into rows: `rowsFromAnswers`; the discovery file's pools by token: `discoveryExtract`), `metric-prices.ts` (aggregator prices as `PriceObservation`s, the filter that keeps them from the price job, and `priceJobReferences`, the job's resolution step without its I/O). The reviewed map of which source answers which row: `metrics.sources.json`, each entry with where it was read; a row whose reason comes from the map is keyed by its `reviewedOn`, so an edit of the map moves that date.

**A missing fact is a row with `value` null and the reason, never a zero.** Two kinds: a reason the plan gives (the row and the map decide it, so the row is stamped with the list's time and inserted once: `not_a_dollar_yield_token`, `not_an_exchange_rate_token`, `no_issuer_source_in_map`, `no_free_indexer`, `no_reviewed_protocol_source`, `no_reviewed_quoted_source`, `no_free_exchange_rate_read`, `no_realised_method_for_its_mechanism`, `in_yield_observations`, `native_token_no_supply_call`, `native_balances_not_read`, `native_token_not_listed`), and a reason a read gives, stamped with the read (`no_registered_pool`, `no_measured_pool`, `no_dexscreener_pair`, `rpc_method_unavailable`, `largest_accounts_refused`, `insufficient_history`, `insufficient_price_history`, `not_priced_by_source`, `read_failed`, …).

**Facts at every change (DA12).** A row equal to the newest stored row of its token and metric (same value or reason, same source), no older and less than a day newer (a week for a daily metric), is not written again. So a second run on the same answers inserts nothing, and an hourly supply that does not move is one row a day, not twenty-four.

## Hourly bars from the held trades (AS.7)

```sh
RISK_DATA_DIR=…/data/risk pnpm risk:assets-bars solana [--dry-run]                 # Step 5b's 34 pools
RISK_EVM_DIR=…/Colosseum-data/risk-evm pnpm risk:assets-bars robinhood [--dry-run]  # RU.14's walk, read-only
pnpm risk:assets-bars-check <solana|robinhood>                                      # against risk_pool_flow
```

- **`bars.ts`** (the command) reads the held event files through **`bars-read.ts`** (no RPC) and upserts `market_bars` under `bars-0.1`: one row per pool and hour it logged a swap, and one per token and hour across the pools it is filed under (`pool = 'asset'`). A second run rewrites the same rows. `detail.layer` is `raw_events`; `source` names the files; `fetched_at` is the day file's `.done` time on Solana and the walk's end on Robinhood Chain; `provenance` is the source rows'.
- **The bar** is `@colosseum/risk`'s (`packages/risk/src/assets/bars.ts`): a swap's price is the quote amount over the token amount (the venue's fee included); open, high, low and close from the swaps that are not dust, open and close by place in the chain; VWAP Σ quote ÷ Σ tokens over every swap; dollars are the quote figures × the hour's `quoteUsd`. **Dust** is a swap with fewer than 10,000 raw units on either leg (its price is the rounding of a few units) or worth under $1 in a priced hour (`DUST_RAW_UNITS`, `DUST_USD`): it stays in the swaps, the volumes and the VWAP, is counted in `detail.dustSwaps`, and sets the marks only of an hour with nothing else (`detail.marksFromDust`).
- **A token's bar** across its pools: on Robinhood Chain the place (block, log index) orders every pool's swaps; on Solana only the slot does (the place inside a slot is each pool's own walk), so in a slot shared by pools the open is taken from the pool whose address sorts first and the close from the pool whose address sorts last, and `detail.openInSharedSlot` / `closeInSharedSlot` say so; `detail.openPool` and `closePool` name them.
- **The quote in dollars is exactly what `risk_pool_flow` used**, so the two reconcile: on Solana the pool's hourly reconstruction (`history-full/hourly/<pool>.jsonl`: USDC at par, other quotes implied from the asset's USDC pool); on Robinhood Chain `hourlyRows` of `scripts/risk-evm/history.ts` over the whole walk (USDG at par; another stock at its own dollar pool's price; the gas coin at the chain's median). **USDC at par and USDG at par are inherited from those methods; no gate records them** (D20 records JupUSD), pending Rodrigo (`docs/risk/PLAN-ASSETS.md` DA21). Every row names its method in `quote_usd_method`: a pool's (`usdc_at_par`, `usdg_at_par`, `implied_from_<pool>`, `native_median_of_<n>_pools`), a token's as its priced pools' methods joined by `; `, and a row with no dollar figure why (`none:quote_decimals_unknown`, `none:no_dollar_price_for_the_quote_this_hour`, `none:no_swap_with_a_side`, `none:no_pool_priced`). An hour without a price, or a pool whose quote decimals the registry does not give, counts its swaps as `unpriced_swaps`.
- **Two differences from the flow import, kept on purpose:** a Robinhood v4 swap that logged nothing going in is not a purchase: it stays out of the sides and is counted in `detail.swapsWithoutSide` (an hour with only such swaps keeps a bar with no swap); and the sides of a pool without quote decimals come from the signs of its amounts, where the flow import counts them all as purchases.
- **The check** (`bars-check.ts`) sums each pool's bars over each `risk_pool_flow` row's window (24 h, 7 d, 28 d to its `data_to`) and regime (the bar's `detail.regime`, set by the flow import's own rule: the hour's row, else the first swap read) and compares swaps, sides, unpriced swaps and the two dollar sums. Counts must be equal; dollars equal or within the float summation bound (`withinRounding`: 2·n·ε·|sum| with n the hours summed, since each hour adds its swaps in the import's own order and only the hours' sums are reordered). Each differing row gets its cause where the check can show it (`swaps_without_side`, `sides_of_a_pool_without_quote_decimals`, `history_extended_after_import`, `hourly_prices_rebuilt`), else `unexplained`; the full list goes to `<ASSETS_DATA_DIR>/<chain>/bars-check-<stamp>.json`.
- **Tests:** `tests/risk-layer/assets-bars.test.ts` on real hours frozen by `freeze-bars-fixture.ts` (`fixtures/risk/assets/bars/`), every figure worked out by hand from the raw amounts, plus the dust rule and the shared-slot order by hand.

A gzip file may hold several members, one per piece.
- **The budget (DA14, amended):** at most 35 GB of new data under `<out>`, and never below 25 GB free (`fitsBudget`), checked before a fetch and after every piece (Robinhood Chain, Chainlink) or day (Solana) against the largest piece so far (`budgetGuard` in `backfill-gate.ts`); when crossed the run stops with `stopped_by_budget`, exit 2, and what it wrote is recorded and resumable. `--all`, and any window wider than a sample (1,000,000 blocks on Robinhood Chain, 2 days on Solana: `MAX_SAMPLE_WINDOW`), runs only when the newest count of the same scope fits (`gateWholeSeries`; scopes `logs`, `feeds`, `pools` and `pools-exact`, `mint` and `authority`, `rows`). `solana-swaps --fetch --all` runs the exact signature pass first, gates again on its count, then fetches the 90 days and the sampled walk; `solana-mints --all` is refused (DA20: mints or mint authorities is Rodrigo's).
- **Robinhood Chain's endpoint:** nothing is read from minute 1 to minute 14 of an hour; before every request and every retry `requestSlot` waits those minutes out and gives the request a timeout that ends before minute 1 (it waits the minutes out instead when under 15 s would be left), on a client with no retries of its own (`retries: 0`), so no retry escapes the check; a refusal for size halves the window, a filter with no address is cut to the 30,000 blocks the endpoint allows; rate, outages and a Cloudflare 403 wait 30 s to 10 min and ask again.
- **Solana's anchored pages:** `getSignaturesForAddress(address, { before: <a signature at time T>, limit })` gives the signatures just before T; a page at each of a fixed set of times (now, every 15 days to day 90, monthly to 2025-06-25) gives the rate there, and a short page reaches the address's first transaction. The anchors are signatures of walks already on disk (the lending history's day files, Step 5b's), chosen by date and never fetched. Calls go through `scripts/risk/lib-pools.ts`'s `rpc()`; run with `DOTENV_CONFIG_PATH` set to the main checkout's `.env`, or they silently use the public endpoint (the count file names which).
- **Tests:** `tests/risk-layer/assets-backfill.test.ts`: the pure parts by hand; a recorded fetch and a recorded Chainlink count and fetch replayed (`fixtures/risk/assets/backfill/`, recorded with `--record <file>`); a list-wide fetch after a sample writing nothing twice; the budget stopping a fetch between pieces; a Solana window with a failed transaction left uncovered and completed without duplicates; the gates (newest count of the scope, wide windows, the command's refusals).
