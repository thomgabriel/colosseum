# The asset universe, one file per chain

`pnpm risk:assets <chain>` (`docs/risk/PLAN-ASSETS.md` AS.2 and AS.3, gate `ASSET-UNIVERSE`, decision DA2) writes `solana.json` and `robinhood.json` in this folder: every token of the classes the product knows on that chain, whether or not a plan may hold it, each with a status and its reason. They are generated and committed, as the stock lists in `scripts/risk/universe/` are, and those stock lists are not changed: a tracked stock's row here names its row there (`tracked`) and copies neither its pools nor its oracle.

```sh
pnpm risk:assets solana      # the Solana builder, scripts/risk/assets/solana.ts
pnpm risk:assets robinhood   # the Robinhood Chain builder, scripts/risk-evm/assets.ts
```

## How a list is made

- **`build.ts`** loads the chain's builder (each exports `buildList(args: string[]): Promise<{ list, lines? }>`), validates what it returns with `UniverseList` (`packages/schemas/src/asset-universe.ts`), checks that every verdict of `<chain>.verdicts.json` names a row of the list, writes `<chain>.json`, formats it, and prints the counts per category, status, class, deciding layer and null reason and each read's calls and seconds. A list that does not validate, or a verdict for an address that is not a row, writes nothing.
- **The builder** reads the chain and its listings and decides which verdict rules each token matches. It never types a verdict.
- **The verdicts** are `<chain>.verdicts.json` (schema `UniverseVerdicts`), reviewed by hand: `rules` for every token a listing names in one way, each with its sources, and `verdicts` for one address each. The builder refuses a verdict for an address it did not read (`unreadVerdicts`), and the command checks it again on the list.
- **A row** is joined by `universeRow` in `packages/risk/src/assets/universe.ts`: the identity read on chain, the context from the chain's own files (pools, oracle, shelf, tracked row), and the verdict fields, taken in this order with the later winning: what the builder derived by a method it states, each matching rule in the table's order (each once), the token's own verdict; the row's `decidedBy` names the layers. The class is always the category's (`CATEGORY_CLASS`). A field no layer sets stops the run, naming the token and the field.
- **What the schema refuses besides missing reasons:** a status that offers what the plan holds out (a permissioned token, a token with a maturity or in another currency, a token with no class, a dollar-yield token with no leg type: these are `held_out` or `excluded`); a tracked stock without its tracked row, or any other row pointing at one; a standard, a symbol source, an authority or the issuer registry of the other chain; an EVM implementation without a proxy.

Nothing in a row is a price, a TVL, a supply or a yield: those are observations with their own time (AS.4 and AS.5).

## Robinhood Chain

`pnpm risk:assets robinhood` (AS.3). The reads and how often each endpoint is asked are in `scripts/risk-evm/README.md` ("The asset universe"); the builder is `scripts/risk-evm/assets.ts`, the list from the reads `scripts/risk-evm/assets-list.ts` (no I/O), the decoders `packages/risk/src/assets/evm.ts`.

**Inputs.** Read: the issuer's registry (`https://api.robinhood.com/rhj/assets`, every row), Chainlink's directory (`feeds-robinhood-mainnet.json`), DexScreener's search and token pairs on the chain, and the chain at one block. Files: the tracked list (`scripts/risk/universe/robinhood.json`), the shelf fixture (`packages/engine/src/personal/fixtures/shelves/robinhood-yield.json`), the deploy record (`deployments/robinhood-testnet.json`), `content/stocks/robinhood.json`, `packages/engine/src/personal/leg-types.ts`, the screening note and its input list (`docs/vault/research/yield-shelf/robinhood.md`, `inputs/robinhood_chain_yield_assets.csv`: every full address written in them is a name to read), the discovery file of RU.2 (`RISK_EVM_DIR`, read only) and the market calendar.

**Which tokens are rows.** Every token of the registry; the gas coin (`0xeeee…eeee`, standard `native`); and each token another listing named that a verdict or a rule decides. DexScreener's names are read on chain when the symbol names a class (it holds USD or EUR, or is one of the prompt's names, a base asset of the directory or a symbol of the registry) or when the verdict table names the address; every such token, and every token the note names, must be decided or the build stops, naming it. Other names (memecoins, launch tokens) are not read and not enumerated (DA6). An address that does not answer `decimals()` and `symbol()` is not a token and never a row (the note's pools, factory, quoter and the rUSDG vault).

**One rule for memecoins and protocols, both chains** (ASSET-1 review, 2026-10-12). What CoinGecko files a token under decides it, by one list for both chains: Robinhood Chain reads the categories' names, matched whole; the Solana list reads the same categories by their CoinGecko ids (its builder is on the branch `universe/assets-solana`, 5e9ca713, which this branch does not change):

- A token in any memecoin category is **not a row**. A memecoin category is one whose name holds "Meme" and not "Ecosystem", or holds "Themed": "Meme", "Robinhood Chain Meme", "Dog-Themed", "Wall Street Bets Themed".
- A token is **`governance`** only when CoinGecko files it under one of exactly these nine categories: Decentralized Exchange (DEX), Lending/Borrowing Protocols, Perpetuals, Derivatives, Oracle, Bridge Governance Tokens, Infrastructure, Liquid Staking Governance Tokens, Yield Aggregator; or under Launchpad when it is the launch pad's own token (CoinGecko keeps a category named "<the pad> Launchpad" of the tokens launched on it: "Pons Launchpad" for Pons); or when its own verdict cites its project's own page naming the protocol it governs. An own page is what `isOwnPage` (`scripts/risk-evm/assets-list.ts`) accepts: an `https://` URL whose host is not a listing, an aggregator, a directory or an explorer (CoinGecko, GeckoTerminal, CoinMarketCap, Jupiter, DexScreener, DEXTools, Birdeye, DefiLlama and llama.fi, Chainlink's sites and its feed directory, the issuer's registry, any `*scan` or `explorer` host, Blockscout); a repository path or any text that is not such a URL never is. The builder stops on a `governance` row that stands on neither, naming it. Nothing else admits a token: not a tag such as DeFi or AI, not a chain (layer 1 or 2), not "Governance" alone, not cross-chain communication, prediction markets, gaming, AI frameworks or DePIN, not what it was launched on or carried by.
- A liquid staking token itself (Liquid Staking Tokens, Liquid Staked ETH, Liquid Restaking Tokens) is `liquid_staking`, not `governance`.
- A token's own verdict wins over every rule, but never makes a memecoin a row: the builder stops on a verdict for a token CoinGecko files as a memecoin, as the Solana builder refuses a row CoinGecko files as one.

**Crypto beyond the listings** (Rodrigo, 2026-10-11). Two more lists name tokens with their address on the chain: CoinGecko's token list for Robinhood Chain (`tokens.coingecko.com/robinhood/all.json`) and Chainlink CCIP's token directory (`docs.chain.link/api/ccip/v1/tokens`, the tokens CCIP moves, with their address on each chain). A token of either, outside the registry, is **selected** when its DexScreener pairs (`tokens/v1/robinhood/<30 addresses>`, read the same day) traded $10,000 or more over 24 hours together, or when its symbol, in upper case, is the base asset of a Chainlink feed of the directory. The volume selects only: it is kept in the frozen reads and never in a row. Each selected token, each verdict's token and each row of a committed list is looked up on CoinGecko (the chain's memecoin category `robinhood-chain-meme`, the list of every coin with its addresses, every category's name, and the coin's page) and decided by the rule above: a protocol's token is a row by `crypto-protocol` (category `governance`, its project as issuer, its CoinGecko page as source; `candidate`, DA6), a liquid staking token by `crypto-liquid-staking`; a memecoin (`meme`), a token with no protocol category (`no_protocol_category`) and one CoinGecko has no page for (`not_on_coingecko`) are not rows. A wrapped coin of another chain or a staking token may be a row by its own verdict, with its source (TAO, wstETH, cbBTC, LINK by CCIP's directory; LINK is `governance` by its Oracle category, not by those sources). `stated.cryptoLeftOut` counts what the selection left out, by reason. CoinGecko is read keyless, one call every six seconds, a minute's wait on a refusal for rate.

**No row leaves unsaid, and an id stays with its address.** Every address of every committed version of `robinhood.json` (its git history) and every verdict's address is read on chain on every run, whatever that day's search returned. Such a row stays a row unless it no longer answers as a token or the rules above now say it is not one (a memecoin by CoinGecko, or a `governance` row with no protocol category and no own page); each row that leaves is named in `stated.leftTheList` with why. A row keeps the id its address had in the newest committed list that held it; the exceptions are an id over the schema's 96 characters and an id the product's deploy records use (`packages/sdk/deployments/*.json`, for example `robinhood:usdc`, the cash id of the mock and local records) on a row that is not listed. A bare id goes only to a listed row or to the one row whose symbol gives it; any other takes a dash and six hex digits of its address. The committed lists the run started from are frozen with its reads, so the test rebuilds the ids.

**How a rule's `match` is read.** Each key must hold for the token: `listing` is a listing that named it (`issuer_registry`, `screening_note`, `position_manager_weth9`, `dexscreener`, `coingecko`, `chainlink_ccip`, `previous_list`, `verdict_table`); `coingecko` is what CoinGecko says of a token outside the registry (`protocol`, `liquid_staking`, `stablecoin`, `meme`, `no_protocol_category`, `not_on_coingecko`); `protocol` is `yes` where that is `protocol` or `liquid_staking`, else `no`; `inUniverse` is `yes` for a token the selection kept or a row of a committed list; `classTable` is `CLASS_BY_UNDERLYING` of `scripts/risk/universe/list.ts` at the registry's symbol (SPY and QQQ `etf`, GLD `gold`, SLV and USO `commodity`, SGOV `dollar_yield`), `stock` for every other registry symbol; `symbolOf` is `issuer_registry` for a token outside the registry whose symbol is a registry token's; `claims` is, for such a token, `issuer_product` where its name names the issuer or that stock (it holds "Robinhood", is the symbol, or begins with the first word of the stock's name in the registry: "GameStop", "Palantir", "SpaceX"), else `none` ("Pawlantir", "A Meme Dog", "NetNet"). A key the builder does not know stops the build.

**The rule over the registry.** `issuer-registry` (issuer Robinhood, a tokenization issuer; access, how dividends reach a holder and how a token is minted and redeemed `not_read_on_an_issuer_source`, each said in `unverified`) and one class rule per `classTable` value: `tokenized_stock`, `tokenized_etf`, `tokenized_gold`, `tokenized_commodity`, `treasury_fund_open`. The builder derives the underlying (the registry's symbol), the leg types (leg-types.ts at the symbol, for SGOV `rate`; none for the others) and the status.

**Status.** `listed`: a tracked stock (`tracked_stock`; its oracle and pools are read in its tracked row, `in_tracked_row`), or a token a deploy record names (`deploy_record`: the model of an asset of `deployments/robinhood-testnet.json` by its `modelOf`, matched to the registry token of that symbol, or the cash token `contracts/script/config/4663.json` names by address, `cashToken`). A registry token that is neither: `candidate`, "outside the cut that names the tracked stocks (gate UNIVERSE)" (DA16). The dollar and yield tokens of the note: its verdict (add with caution `candidate`; hold `held_out`; out `held_out`, or `excluded` where the reason is filter 4, not live; the PT `fixed_maturity`, `held_out`), with `verdictSource` naming the note and section. Crypto: `candidate` (DA6) where a listing gave the address with a source (WETH9() of the position manager, the note's input list), `held_out` where only DexScreener names it. Pool shares and yield claims: `held_out` (no class). A dollar not screened: `held_out`. A token not shown to be the asset it names (the note's "USDT", two "GOLD"): `held_out`, with what was read in `unverified`. Not the asset it claims: `excluded`, by the rule `not-the-issuers-stock-token` for a token with a registry stock's symbol whose name claims that stock and that the registry does not hold, by `registry-symbol-not-a-protocol` for one with such a symbol that does not claim the stock and that no protocol category names (a symbol alone never excludes a protocol's token: NET, a lending protocol's by CoinGecko, is decided by its categories), by its own verdict where its own name says so (two "USDC" that call themselves dog and cat coins, a WBTC that calls itself We Buy The Cat).

**What a verdict writes.** A decision with its source, never a figure: no price, rate, yield, TVL, discount or cost sits in a verdict's text; it points at the note's section instead. `access` is written only as a source states it (the note's reading of a token's transfer gates, an issuer's eligibility terms), else `null` with `not_read`.

**What the code says.** `proxy` from the EIP-1967 slots (implementation, admin, beacon; a beacon's `implementation()`): `false` where they are zero and the code has no DELEGATECALL, or the code is an EIP-1167 clone whose target has none; `null` where the code delegates without a slot or a clone's target delegates (the target's own slots are read and named in `read`). `pausable` and `blacklist` are `true` where the code that runs (a proxy and its implementation, or a clone's target) pushes a selector below, or where that code is a facet router (it pushes `getFacet(bytes4)` 112b6a67) and `getFacet(<selector>)` asked of the token names a facet whose own code pushes it; `null` (`code_may_run_elsewhere`) where none is found and the code that runs has a DELEGATECALL; `false` only where none is found in code that does not delegate.

Who an AccessControl contract lets act is not read.

**What is stated in the file** (`stated`): the rows, the enumeration, the class names, the rules, what is derived, `listed`, the ids, the identity, the standard, the extensions, the authorities, the oracle (the oracle map's rule, letters as written; no feed for a token whose issuer no verdict names, `issuer_not_confirmed`; `feed_named_in_other_case_not_tied` where the directory names the symbol only in another case; no answer stored), the pools (a pool with a registry stock token counted from the discovery file of Oct 5, confirmed when a chain source names it; any other from this run's DexScreener answers, unconfirmed; the venues that are not Uniswap v3 or v4 are not read, D4, `BYREAL-D4`), and that nothing is a figure.

## Solana

```sh
DOTENV_CONFIG_PATH=<main checkout>/.env pnpm risk:assets solana \
  --registry <main checkout>/data/risk/registry-20261001T0139.json \
  --reads-dir <main checkout>/data/assets/solana     # live: reads, saves them, writes solana.json
pnpm risk:assets solana --from <solana-reads-<stamp>.json[.gz]>   # rebuild from saved reads, no network
pnpm risk:freeze-assets-solana <solana-reads-<stamp>.json>        # freeze them for the test
```

The builder is `solana.ts` (all I/O) and `solana-list.ts` (the list from the reads; no I/O, no clock). The byte decoders are `packages/risk/src/assets/spl-mint.ts` (`decodeMint`, `decodeMetaplexMetadata`, `solanaIdentity`), tested on frozen mainnet accounts. `SOLANA_RPC_URL` loads through dotenv; without it the scripts fall back to the public RPC.

**Inputs, in the prompt's order (5.2), each read recorded in `list.reads` with its calls, seconds, rows and errors.** Jupiter's verified list, live (`lite-api.jup.ag/tokens/v2/tag?query=verified`), every tag kept and cut to id, symbol and tags; `risk_lending_pools` in the local Postgres (one read-only `SELECT`), whose mints and debt mints name dollar tokens and the reserves' Scope chains; the research note `docs/vault/research/yield-shelf/solana.md` (every full address in backticks) and its shelf fixture; DefiLlama's stablecoins and protocols on Solana in the RWA and yield categories, as names only; the issuers' pages of `solana.issuer-mints.json`, each fetched again and searched for the mint it is said to print. Read as files: the tracked list, the structurer's registry, `deployments/solana-devnet.json`, the Scope table, `content/stocks/solana.json`, the launch-shelf seed, the engine's leg types and the pool registry `data/risk/registry-20261001T0139.json`. Then every candidate's mint by `getMultipleAccounts` (100 a call, the slot kept per call) and, for each mint that holds no metadata of its own, its Metaplex metadata account at the derived address. A Jupiter token is a candidate when it carries a tag a rule asks for or has a verdict; every address another source names is a candidate.

**How a rule's `match` is read** (`MATCH_KEYS` in `solana-list.ts`); every key must hold, and an unknown key stops the run:

| Key | Holds when |
|---|---|
| `jupiterTag` | Jupiter's verified list carries the tag for the token |
| `minter` | the mint authority read on chain is this address |
| `freezeAuthority`, `permanentDelegate` | that authority, read on chain, is this address |
| `program` | the token program read on chain is `spl` or `token2022` |
| `nameEndsWith` | the name the chain answers ends with this text |
| `nameKind` | what the name method (`kindOfName`) reads in a stock issuer's token's name: `stock`, `equity_etf`, `gold_fund`, `commodity_fund`, `treasury_fund`, `bond_fund`, `crypto_fund`, `leveraged_etf` |
| `listedIn` | the token is on today's shelf that way (`structurer_registry`, `deploy_record`, `tracked_stock`), or `any`, or `none` |

The stock issuers' rules rest on keys read on chain: one mint authority for xStocks and for Ondo, one freeze authority and permanent delegate for Backpack's tokens. The `lst` rule rests on Jupiter's tag alone, as no key read on chain is shared by the stake pools. A stock issuer's rule is matched first, so the name method can read the ticker; then every rule is matched. A token Jupiter tags `deprecated` is not a row, nor one whose rules leave a verdict field unset; both are named in `stated.rules`.

**What the builder derives**, the lowest layer of `decidedBy`, only for a token of a stock issuer's rule (`xstocks`, `ondo-global-markets`, `backpack-securities`): `underlying`, the chain's symbol less the issuer's suffix (`x`, `on`; Backpack's symbol is the ticker); `category`, from what the name the chain answers says the token is (`kindOfName` in `solana-list.ts`, tested on real names). The tracked list's class table (`CLASS_BY_UNDERLYING`: SPY and QQQ funds of shares, GLD gold, SLV and USO commodities, SGOV Treasuries) wins where it names the ticker. Otherwise a name with no fund word (ETF, ETN, Fund, Index, a fund-only sponsor such as iShares, SPDR or Vanguard, an index such as S&P 500 or Russell 2000) is a stock; a fund is, in this order, leveraged or inverse (2x, 3x, Bull, Bear, UltraPro, ProShares Ultra or Short), of crypto assets, of gold, of another commodity (miners, services and producers are shares, not the metal), of Treasuries or government bonds, of other bonds or income, else of shares. Categories: a stock `tokenized_stock`, a fund of shares `tokenized_etf`, gold `tokenized_gold`, a commodity `tokenized_commodity`, Treasuries `treasury_fund_open` with no leg type (`not_screened_on_solana`), a leveraged, crypto or bond fund `tokenized_etf`. The rules `stock-issuer-*` hold out every fund that is not screened. A name without a fund word is a stock whatever the token is (JPSTx, a short-bond fund, is one).

**Context.** `id`: the tracked list's, else the shelf fixture's, else `solana:<slug of the chain's symbol>` (`+` as plus, `*` as star); two rows on one slug each take the first six characters of their address. `listedIn`: by mint in the structurer's registry; as the model of a test-network token (`modelOf`, matched to the one named mint that answers that symbol); a tracked stock. A tracked stock's row names its tracked row and reads its pools and oracle there (`in_tracked_row`). `oracle`: a Scope entry of the Scope table, else a one-entry Scope chain of a Kamino reserve of the lending import; `no_scope_entry` where a reserve of the import holds the token and names no chain, `scope_not_read` where none does (the import holds only the xStocks markets). A Pyth feed the launch-shelf seed names goes in `unverifiedOracles`, never read. `pools`: the registry file's pools that hold the mint on either side, else `no_registered_pool`; that registry was built for the stock tokens, so the count is the pools a token shares with a stock token. `attributes`: an xStock's row of `content/stocks/solana.json`, by symbol.

**Status rules**, which the verdicts follow: `listed` where `listedIn` is not empty; a stock token outside the cut that names the tracked stocks `candidate` (DA16); a fund among them that is not screened (Treasuries, bonds, crypto, leveraged or inverse) `held_out`; dollar yield by the research note's verdict (add, add with caution: `candidate`; hold: `held_out`; out: `held_out` or `excluded` by its reason), `verdictSource` naming the note and section; a dollar-yield token the research has not screened `held_out`; permissioned funds `held_out` (DA4); another currency `held_out` (USD-ONLY, DA7); crypto `candidate` (DA6); a maturity or no class `held_out`; defunct, exploit-linked or not the asset it claims `excluded`. Leg types come from the note and are held to `packages/engine/src/personal/leg-types.ts` by the shelf fixture's symbol: a difference stops the run.

**`access`** is set only where a source says it: `permissioned` (an allowlist or terms that bar the holder: the permissioned funds, eUSX), `front_end_geo_blocked` (the issuer bars countries from minting or buying: USDY, the Etherfuse tokens, ONyc), else `null`, `not_read`.

## Metrics: the facts over time of every row (AS.5) and their jobs (AS.6)

`pnpm risk:assets-import <solana|robinhood|all>` reads every metric of every row of a list from free sources (DA8) and writes `asset_observations` (one row per chain, token, metric, source and time; migration `0021`); the aggregators' prices go to `risk_price_observations` under their own source. Gate `ASSET-METRICS`.


Options: `--dry-run` (no row, no answers file, no run-log line), `--metrics` (any of the nine below and `price_usd`), `--from` (one chain, no network), `--data-dir`, `--solana-prices none|unresolved|all` (below), `--answers-out <file>` (the answers to a file of your choice, a dry run included), `--only` and `--show` (some tokens: a try, a fixture's run; never a job's run). Each run writes its raw answers to `<data-dir>/<chain>/metrics/<stamp>.jsonl.gz` (a header, then one line per read) and appends one line to `<data-dir>/runs.jsonl`: per read its calls, seconds, errors and rows; per metric the rows with a value and the rows null by reason; per token the reads that failed; what was written.

**Where the code is.** Pure, in `packages/risk/src/assets/` (no I/O, no clock, no `process.env`, never `engine`): `metrics.ts` (one builder per metric, its method in `method`, `method_version` `asset-metrics-0.1`, its parts in `detail`; `metricPlan`, which read answers a metric of a row or why none does), `metric-rows.ts` (a run's answers into rows: `rowsFromAnswers`; the discovery file's pools by token: `discoveryExtract`), `metric-prices.ts` (aggregator prices as `PriceObservation`s, the filter that keeps them from the price job, and `priceJobReferences`, the job's resolution step without its I/O). I/O: `metrics-solana.ts` (Solana), `scripts/risk-evm/assets-metrics.ts` (Robinhood Chain), `metrics-io.ts` (DexScreener, DefiLlama, the issuers), `metrics-db.ts` (the reads and writes of the database), `metrics-run.ts` (one run, shared by the import and the jobs). The reviewed map of which source answers which row: `metrics.sources.json`, each entry with where it was read; a row whose reason comes from the map is keyed by its `reviewedOn`, so an edit of the map moves that date.

**A missing fact is a row with `value` null and the reason, never a zero.** Two kinds: a reason the plan gives (the row and the map decide it, so the row is stamped with the list's time and inserted once: `not_a_dollar_yield_token`, `not_an_exchange_rate_token`, `no_issuer_source_in_map`, `no_free_indexer`, `no_reviewed_protocol_source`, `no_reviewed_quoted_source`, `no_free_exchange_rate_read`, `no_realised_method_for_its_mechanism`, `in_yield_observations`, `native_token_no_supply_call`, `native_balances_not_read`, `native_token_not_listed`), and a reason a read gives, stamped with the read (`no_registered_pool`, `no_measured_pool`, `no_dexscreener_pair`, `rpc_method_unavailable`, `largest_accounts_refused`, `insufficient_history`, `insufficient_price_history`, `not_priced_by_source`, `read_failed`, …).

**Facts at every change (DA12).** A row equal to the newest stored row of its token and metric (same value or reason, same source), no older and less than a day newer (a week for a daily metric), is not written again. So a second run on the same answers inserts nothing, and an hourly supply that does not move is one row a day, not twenty-four.

## Hourly bars from the held trades (AS.7)

```sh
RISK_DATA_DIR=…/data/risk pnpm risk:assets-bars solana [--dry-run]                 # Step 5b's 34 pools
RISK_EVM_DIR=…/Colosseum-data/risk-evm pnpm risk:assets-bars robinhood [--dry-run]  # RU.14's walk, read-only
pnpm risk:assets-bars-check <solana|robinhood>                                      # against risk_pool_flow
```

- **`bars.ts`** (the command) reads the held event files through **`bars-read.ts`** (no RPC) and upserts `market_bars` under `bars-0.1`: one row per pool and hour it logged a swap, and one per token and hour across the pools it is filed under (`pool = 'asset'`). A second run rewrites the same rows. `detail.layer` is `raw_events`; `source` names the files; `fetched_at` is the day file's `.done` time on Solana and the walk's end on Robinhood Chain; `provenance` is the source rows'.
- **The bar** is `@colosseum/risk`'s (`packages/risk/src/assets/bars.ts`): a swap's price is the quote amount over the token amount (the venue's fee included); open, high, low and close from the swaps that are not dust, open and close by place in the chain; VWAP Σ quote ÷ Σ tokens over every swap; dollars are the quote figures × the hour's `quoteUsd`. **Dust** is a swap with fewer than 10,000 raw units on either leg (its price is the rounding of a few units) or worth under $1 in a priced hour (`DUST_RAW_UNITS`, `DUST_USD`): it stays in the swaps, the volumes and the VWAP, is counted in `detail.dustSwaps`, and sets the marks only of an hour with nothing else (`detail.marksFromDust`).
- **A token's bar** across its pools: on Robinhood Chain the place (block, log index) orders every pool's swaps; on Solana only the slot does (the place inside a slot is each pool's own walk), so in a slot shared by pools the open is taken from the pool whose address sorts first and the close from the pool whose address sorts last, and `detail.openInSharedSlot` / `closeInSharedSlot` say so; `detail.openPool` and `closePool` name them.
- **The quote in dollars is exactly what `risk_pool_flow` used**, so the two reconcile: on Solana the pool's hourly reconstruction (`history-full/hourly/<pool>.jsonl`: USDC at par, other quotes implied from the asset's USDC pool); on Robinhood Chain `hourlyRows` of `scripts/risk-evm/history.ts` over the whole walk (USDG at par; another stock at its own dollar pool's price; the gas coin at the chain's median). **USDC at par and USDG at par are inherited from those methods**, confirmed by Rodrigo on 2026-10-13 (gate `DA21-PAR`; `docs/risk/PLAN-ASSETS.md` DA21). Every row names its method in `quote_usd_method`: a pool's (`usdc_at_par`, `usdg_at_par`, `implied_from_<pool>`, `native_median_of_<n>_pools`), a token's as its priced pools' methods joined by `; `, and a row with no dollar figure why (`none:quote_decimals_unknown`, `none:no_dollar_price_for_the_quote_this_hour`, `none:no_swap_with_a_side`, `none:no_pool_priced`). An hour without a price, or a pool whose quote decimals the registry does not give, counts its swaps as `unpriced_swaps`.
- **Two differences from the flow import, kept on purpose:** a Robinhood v4 swap that logged nothing going in is not a purchase: it stays out of the sides and is counted in `detail.swapsWithoutSide` (an hour with only such swaps keeps a bar with no swap); and the sides of a pool without quote decimals come from the signs of its amounts, where the flow import counts them all as purchases.
- **The check** (`bars-check.ts`) sums each pool's bars over each `risk_pool_flow` row's window (24 h, 7 d, 28 d to its `data_to`) and regime (the bar's `detail.regime`, set by the flow import's own rule: the hour's row, else the first swap read) and compares swaps, sides, unpriced swaps and the two dollar sums. Counts must be equal; dollars equal or within the float summation bound (`withinRounding`: 2·n·ε·|sum| with n the hours summed, since each hour adds its swaps in the import's own order and only the hours' sums are reordered). Each differing row gets its cause where the check can show it (`swaps_without_side`, `sides_of_a_pool_without_quote_decimals`, `history_extended_after_import`, `hourly_prices_rebuilt`), else `unexplained`; the full list goes to `<ASSETS_DATA_DIR>/<chain>/bars-check-<stamp>.json`.
- **The hosted hourly jobs** (gate `HOURLY-BARS`, `scripts/ops/install-hosted-bars.sh`): Robinhood Chain's runs `bars.ts robinhood --lookups-only --walk <dir>`, which first walks the chain's last hours into its own folder (`scripts/risk-evm/recent-walk.ts`) and writes the complete hours no earlier run wrote; Solana's runs **`mid-bars.ts`** (`pnpm risk:assets-mid-bars [--since-hours 6] [--dry-run]`), token bars under `mids-0.1` from `risk_pool_snapshots` (`midBars` of `@colosseum/risk`: one USDC pool of tier A or B an hour, the deepest by its median 2% depth; mids, no swap, so no volume); `--fill-from-files [dir]` builds the same bars once from the collector's day files for the hours before the database's snapshots. An hour neither job wrote (the collector down) is an hour the lookups count as missing: a window is shown while no more than 5% of its hours are missing, each figure saying how many (gate `HOURLY-BARS` as amended 2026-10-22, `barCoverage`), and withheld with more, or when the newest bar ended more than two hours before now. Tests: `tests/risk-hourly-bars-robinhood.test.ts`, `tests/risk-layer/asset-mid-bars.test.ts`.
- **Tests:** `tests/risk-layer/assets-bars.test.ts` on real hours frozen by `freeze-bars-fixture.ts` (`fixtures/risk/assets/bars/`), every figure worked out by hand from the raw amounts, plus the dust rule and the shared-slot order by hand.

The backfill's files (AS.8) into the tables, from the files alone (the one chain read is `risk:assets-resolve-pools`, below). **Bars:** a new key is inserted; a key an earlier run of this import wrote (its `source` names a backfill day file, or a token row the backfill's day files) is replaced only when the row now differs, for example a pool resolved since, a pricing method added, or more pools in an hour's median; a key of any other source (AS.7's held history) is never touched (`upsertBackfillBars`). **Withdrawn:** a key this import wrote, in the days its files on disk span, that the current build no longer produces (a day no longer whole, its manifest reopened, a pool moved to another token, a registry change) is deleted (`reconcileBackfillBars`; `withdrawn` in the output, counted and not deleted under `--dry-run`). So a re-run on the same files changes nothing, and the backfill's rows always equal what a run on today's files builds. **Daily series:** inserted, never updated. `--dry-run` builds and counts and writes nothing (the bars command still reads `market_bars` to say how many of its rows are there already, `alreadyStored`: `equalSource`, `earlierImport`, `otherSource`).

- **Whole days only.** A day file is read only when the fetch's own records hold its UTC day whole, so a fetch still running is never read mid-write. Solana: the manifest's covered seconds hold the day from 00:00:00 to 23:59:59 (`wholeDaysOfSeconds`, the rule of `daysCovered`). Robinhood Chain: its records are blocks, and none maps a block to a time; the covered blocks are `fetched.json`'s ranges for both swap filters (`v3_swap`, `v4_swap`) under the list's `*` and the shelf's scope, and every subject's manifest (swaps, supply, liquidity) says on which days its rows fell; a manifest whose pieces all lie inside one covered range shows a block of that range on each of its days, so the days strictly between the oldest and the newest such day are whole (`wholeDaysOfBlocks`). A manifest with a piece outside the range (a piece being written) is not used, nor one whose pieces come within `DEFAULT_HEADER_STEP` (10,000) blocks of the range's ends: a row's time is interpolated between headers that far apart, so a row filed on the day before could be past midnight, and the margin keeps the day's true first and last blocks inside the range. A manifest with a failed reopen check (`recheck_…`, `rewalk_…`, `verify_days_…`: its owner uncovered windows and left their days listed) is not used either (`manifestsReopened`). On Solana only the covered seconds count (the days a manifest lists are never used), so a reopen, which empties the windows it uncovers, is enough; those manifests are counted apart (`manifestsReopened`).
- **Solana bars** (`bars-backfill.ts`, `readSolanaBackfill`): the pools and which side is the asset come from the shelf's registry (`--registry`). A token's day is built only when every registry pool of the token holds it whole, so its `asset` row has all its pools. The quote in dollars: USDC at par (`usdc_at_par`, DA21); another quote implied from the asset's USDC pool, the largest by the registry's TVL that has a price that hour (`implied_from_<pool>`, Step 5b's rule): that pool's volume-weighted price of the hour over this pool's own, the USDC pool's carried at most 24 hours inside the same UTC day and then named so (`implied_from_<pool>_carried_<h>h`); a price of the hour itself, from either source below, wins over a carried one; when the asset has no USDC price that hour, a quote that is itself an asset of the registry whole that day at its own USDC pools' price (`implied_from_<pool>`), and SOL at the hour's native median (`native_median_of_<n>_pools`, `_carried_<h>h` when carried: as Robinhood Chain prices ETH, every SOL-quoted pool of the day that traded in the hour and whose asset has a USDC price that hour implies SOL's dollars, the asset's over the pool's own price, and the hour takes their median weighted by the pools' swaps; carried at most 24 hours inside the day; the registry holds no SOL/USDC pool, SOL being a quote only); else no dollar figure (`none:no_dollar_price_for_the_quote_this_hour`). Of the 11 registry tokens with no USDC pool (RAY, ZEUS, JitoSOL, JupSOL, WETH, WBTC, PYTH, LBTC, AUTO, PRIME, xBTC), those with a SOL pool are priced by the median; LBTC, AUTO, PRIME and xBTC (quoted in cbBTC, PRIME, PYUSD, USDG) only where the quote is a registry asset with a USDC price.
- **Robinhood Chain bars** (`readRobinhoodBackfill`): a pool's tokens come from RU.2's creation logs (`RISK_EVM_DIR/creation-logs-robinhood.json`), then from `<ASSETS_DATA_DIR>/robinhood/pool-tokens.json` (below); a subject neither names is counted (`unresolvedPools`, `unresolvedSwaps`) and gets no bar. The pool is filed under the side less like a quote (USDG, then the list's other dollar tokens, then ETH and WETH, then anything else; a tie goes to the shelf's side, then to token 0), and only when that side is a token of the shelf (the scope's count file names it; else `notShelfPools`). The quote in dollars is `hourlyRows` of `scripts/risk-evm/history.ts` over that day alone: USDG at par (`usdg_at_par`, DA21), a token with its own USDG pool at that pool's price (`implied_from_<pool>`; the asset's USDG pool is the one with the most swaps that day), ETH and WETH at the chain's swap-weighted median (`native_median_of_<n>_pools`).
- **The pools the creation logs do not name** (`resolve-pools.ts`, `pnpm risk:assets-resolve-pools`): every swap subject of the backfill neither the creation logs nor the file names is asked once, by PoolResolver's reads (`poolTokensOf` in `scripts/risk-evm/backfill-logs.ts`: token0(), token1() and factory() of a v3-style pool, poolKeys(id) of the v4 position manager, by Multicall3, 400 calls a request), and kept in `<ASSETS_DATA_DIR>/robinhood/pool-tokens.json` (not committed): its tokens, or null when the chain does not know the id (a v4 pool no position manager holds a position of). Only through `ROBINHOOD_BACKFILL_RPC_URL`, metered by `backfill-cost.ts` into the cost ledger and under the cap the logs fetch shares; it refuses to run without that variable and prints no URL. A Uniswap v3 factory is required of a v3-style contract (D4). The ledger is now read again after each answer, so two runs sharing it keep each other's spend (a run started before this change still writes the ledger it read before its request).
- **What the hosted database keeps (Oct 21).** `pnpm risk:assets-bars robinhood --lookups-only [--since-hours 72] [--drop-old-pool-bars]` writes only the rows the asset lookups read (`lookup-rows.ts`): the token rows of the last hours, with an empty `detail` (no reader uses it; it is a third to a half of a bar), and the rows of each token's top five pools by the newest `pool_tvl_usd` reading in the same database (`topPools`, the lookups' own choice) of the last two days; `--drop-old-pool-bars` then deletes the chain's held pool bars older than that, never a backfill row (a dry run counts them). ## The shelf (AS.9 and AS.10, gate ASSET-SHELF)

`pnpm risk:shelf <solana|robinhood|all> [--floor <dollars>]` (`shelf.ts`; the pure part `shelf-build.ts`, the cut `cutShelf` in `packages/risk/src/assets/shelf.ts`, the one the backfill uses) cuts each chain's shelf from the committed list and the newest `dex_volume_24h_usd` reading of each row in `asset_observations`, and writes three files:

- `shelf-<chain>.json`: the rule, the floor ($100,000 by default), the list and its commit, the reading's time, the counts, and one row per shelf token with its volume and that reading's `source`, `fetched_at`, `method` and `provenance`. Rows go by volume, largest first, so a cut to fewer entries (the Solana program's 64, AS.11) reads from the top.
- `shelf-entries-<chain>.json`: one `basket_assets` row per token (`BasketAsset`), its class taken from the list. Eligibility is the engine's, by class. The tier is **C, a labelled fallback** (`tierFrom: "fallback"`, gate `EXIT-SOURCE`) until Bearing measures the token's exit. `maxWeightBps` is 0 and the deploy-only fields are named under `toSet`, for Thom's asset entries (OPS-4). `priceKind` and `priceRef` come from the list's oracle (the tracked list's for a tracked stock), else `none`. A dollar-yield token without its leg types or a yield reading (a `yield_observations` row of a registry asset at its address) is under `waiting` with what it lacks.
- `fixtures/risk/assets/shelf-readings-<chain>.json`: every reading the cut considered, frozen so `tests/risk-assets-shelf.test.ts` re-cuts the shelf and remakes the entries.

The command refuses a list with uncommitted changes. It reads only the local database and the committed files. It takes only `live` readings. A reading's time is the first of equal readings, as the metrics job rewrites a value only when it changes: the shelf's reading window runs from the oldest such time (a null first read on Oct 11) to the newest.

- **Subjects:** every shelf token but the quotes. Cash tokens (`cls` cash) and SOL are stated, not chosen, as quotes: their own pools (SOL/USDC) would dwarf every other token, so they enter only as another token's pair (`quotesNotSubjects`).
- **Discovery:** DexScreener's `token-pairs/v1/solana/<mint>` per subject (at most 30 pairs), one call every 300 ms, a 429 waited out; the answers go to `shelf-dexscreener-solana-<stamp>.jsonl` (`--pairs` reuses them).
- **The rule** (`SHELF_POOL_RULE`): the pairs on a venue the swap decoders read (Raydium CLMM, CPMM and AMM v4, Orca Whirlpool, Meteora DLMM and DAMM v1 and v2, PumpSwap: `VENUES` in `scripts/risk/lib-venues.ts`; the four before ASSET-3 in the run below), at least $10,000 of liquidity, largest first, until 90% of the token's supported liquidity is covered, at most 5 a token. DexScreener sometimes values a pair at a mispriced quote (on Oct 13 a JitoSOL/JupSOL pool at $2.4 billion; pairs quoted in JupSOL, JLP, MET): a pair whose price of the token is more than 1.5 times off the median of its pairs' prices has its liquidity re-valued at that median, and keeps DexScreener's figure beside it.
- **Confirmation:** each kept pool is read with `getMultipleAccounts`: the owner is the venue's program (any of `ALL_VENUES`; `build-registry.ts` keeps to `REGISTRY_VENUES`, its four) and the decoded mints hold the token; a pool that fails is left out (`excluded`) and the token re-picked. A pool kept for two subjects is written once, under the first.
- **The file** `shelf-registry-solana-<stamp>.json`: `pools` are `RegistryPool` rows (each with `source`, `fetchedAt`, `confirmedAt`, `method`, `provenance`, tier B with its reason, `tvlUsd` DexScreener's liquidity), then `tokens` (picked, covered, left out, unsupported, repriced), `noSupportedPool`, `quotesNotSubjects`, `excluded`. Its name does not start with `registry-`, so `latestRegistryFile`, `history-backfill.ts` and `retier.ts` never take it by default: the backfill takes it only with `--registry`. It writes no table and nothing under `~/.colosseum`.
- **Test:** `tests/risk-layer/shelf-pools.test.ts`, on three real answers frozen with placeholder addresses (`fixtures/risk/assets/shelf-pools/`).

### Solana: the merged registry

```sh
RISK_DATA_DIR=<main checkout>/data/risk pnpm risk:registry-merge --out data/risk   # [--base <file>] [--shelf <file>]
```

`scripts/risk/registry-merge.ts` (the rule in `scripts/risk/lib-registry-merge.ts`, no I/O) reads the stock registry (default the newest `registry-<stamp>.json` of `RISK_DATA_DIR`, its dust left out: the file `retier.ts` copied to `~/.colosseum/risk/registry.json`; `--base ~/.colosseum/risk/registry.json` reads the installed copy, read only) and the shelf registry (default the newest `shelf-registry-solana-<stamp>.json`), and writes `collector-registry-solana-<stamp>.json` and nothing else:

- **The stock pools as installed, and no stock asset gains a pool.** Tier, order and fields unchanged. A shelf pool of a stock-set asset is left out (`shelfLeftOut`: AVGOx's Raydium CLMM pool on Oct 13), because `pools.ts` routes every dollar and SOL pool of an asset into its curve and such a pool would move that stock's curve. The merge does change what the collector does: more pools a run (RPC, run time, the shared cap on re-listing), and new assets downstream (below).
- **Once per address.** A shelf pool the stock registry holds is the stock registry's, with its tier (`duplicates`).
- **The shelf's tiers** by `retier.ts`'s rule, now one function (`scripts/risk/lib-tiers.ts`, `retier.ts` calls it): tier A for the pools that together hold 99% of the TVL of the pools of $1,000 or more (refreshed every 5 minutes), B for the rest (hourly), dust left out. It runs over the shelf's pools alone: over the merged set the shelf's dollars (TRX, syrupUSDC, cbBTC…) would move 511 stock pools from A to B. `TIER_A_SHARE` and `MIN_POOL_TVL_USD` change it, as they change `retier.ts`. Each shelf pool says why (`tierReason`).
- **`set` on every pool** (`stocks` or `shelf`). The shelf pools get what every pool gets: a snapshot per run of their tier (depth within 2%, sell and buy curves where the quote is USDC, USDT or SOL; a pool quoted in another token has its depth in that token and no dollar curve) and the routed curve of their asset (`assets/<day>.jsonl`). The extras stay on the stock set, as before the merge: raw captures and position scans (the 80% rule of `pools.ts`, mirrored in `raw-arrays/lib.ts`), the Jupiter cross-check's asset set (`quotes.ts`), the lending-market snapshot's mints, and the split snapshot's pools (`lib-split.ts`).
- **The name** does not start with `registry-`, so `latestRegistryFile`, `retier.ts` and the backfill never take it.
